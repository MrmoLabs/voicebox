# DSH Voicebox 自然语音对话方案

日期：2026-10-17。版本：设计 v2。状态：首版已实施，实际范围及验证见 VERIFICATION.md 的“自然语音首版”；本文仍包含未完成的目标，不能视为所有场景已通过。

## 1. 产品目标与本次决策

用户开启语音后，通过自然提问、追问和插话完成任务。系统负责组织内容、调整详略、转换表达和接续讲解。正常使用不要求用户管理播报章节、选择摘要策略，或每隔一段时间确认继续。

本稿取代前稿的“默认约半分钟口头摘要，随后等待追问”策略：

- 默认提供足以完成当前问题的口头答复，覆盖所有明确提出的子问题。复杂问题可以连续讲解，不按固定时长截断。
- 用户要求“详细”“全部展开”时，提高解释深度，并自动讲完已经确定的范围；章节之间自然过渡，不逐节征求继续许可。
- 内容深度和表达方式独立。详细讲解仍使用自然口语，逐字朗读是另一种明确请求。
- 一份答复可以包含解释、表格、代码、引用及执行结果。按内容单元组织，不能把整篇简单归类为“摘要”或“全文朗读”。
- 明确记录已播、未播、待展开内容和被打断的位置。已合成、已排队不等于已播放，已播放不等于用户确实听到。
- 保留低延迟流式 PCM、后台播放、当前音色和模型配置，不把整段生成或二次摘要设为新的默认等待环节。

“完整”指覆盖当前任务需要的内容，不要求每次闲聊都生成长篇报告。用户明确说“就一句话”“只讲结论”时按其要求收短，但不能删去会改变判断的必要条件和失败状态。

## 2. 现状与官方接入边界

| 位置 | 当前职责 | 需要新增的能力 |
| --- | --- | --- |
| src/conversation.js | 录音、ASR、两阶段插话、通过当前会话的 beginSubmission / prompt 提交文字 | 区分控制、追问和回应，维护恢复点 |
| src/controller.js | 会话绑定、后台播放、暂停、停止、音频所有权 | 统一执行播放计划，回报实际播放进度 |
| src/live.js | assistant 增量、turn / attempt 隔离、重试和正文变化处理 | 关联内容单元及答复版本 |
| src/sentences.js | 分句、顺序合成、预取、单段及单轮字符保护 | 按章节推进长讲解，保护边界不能变成静默截断 |
| src/bridge.js | 清洗正文、请求 Voicebox；目前会过滤代码和管道表格等 | 清洗只处理发音格式，不能代替语义解释 |
| src/conversation.jsx、src/client.jsx | fixed 悬窗、标题栏入口、回复下方朗读控件 | 控件进入输入区正常布局 |
| src/index.js | 官方 Cordis 宿主插件、连接代理、配置 | 会话作用域的表达上下文及内容状态服务 |

回答来自当前会话模型及其会话上下文、资料和工具结果。Whisper 负责识别，Qwen TTS 负责合成。TTS 不需要模型全部上下文，也不决定答案详略。

早期设计参考树根版本为 0.1.5-rc.1；首版实施已改为从实际安装的 0.2.1-rc.1 提取可信运行文件，核对作用域化的 systemPrompt.context、system-prompt/assemble、conversation.input.dock、工具注册和 AgentLoop 接续，并通过真实宿主测试。客户端视图使用官方插槽。

下文的数据结构是本插件待新增的内部协议，不是现有 DSH API。不假定当前存在 voicebox.say、voicebox.present 或可直接使用的语义播报通道。

## 3. 三层结构：内容、表达、播放

~~~mermaid
flowchart TD
  U[用户语音或文字] --> I[意图与范围解析]
  I --> M[当前 DSH 会话模型和资料工具]
  M --> A[答复内容与版本]
  A --> V[屏幕正文和可复制工件]
  A --> P[口头表达计划]
  I --> P
  P --> Q[分句、预取和实时 PCM]
  Q --> L[实际播放进度]
  L --> I
  L --> C[会话接续上下文]
  C --> M
~~~

三层不能共用一个字符串游标：原文位置、解释内容和音频播放位置不一定逐字对应。

### 3.1 答复内容：AnswerDocument

一个逻辑答复可以由多个模型 step 或解释补充组成，不等于一条消息或一次 TTS 任务。

- 身份：sessionId、answerId、revision，以及原始 turn、attempt、message 引用。
- 结构：有稳定 ID 的 section / unit，保存标题、顺序、类型和父子关系。
- 内容：原始正文、工件引用、必要条件、限制、失败与未验证事项、引用依据。
- 状态：draft / settled / interrupted / superseded。流式单元可先临时建立，提交后关联持久消息；未提交草稿不能当作最终答案。

标题、段落、代码块和表格可以提供初步结构；复杂问题的子问题和解释清单需要主模型标注。Markdown 解析只能确认结构存在，不能证明它理解了所有语义。

屏幕原文仍是可追溯依据。每段口头解释关联相应单元，并提供可展开的讲解文字。新增事实或修正形成新版本或明确补充，不能悄悄改写原来的判断。普通原文和讲解记录要有清楚关系，不保留两份互不对应的“最终答案”。

### 3.2 表达计划：NarrationPlan

- 身份：planId，绑定 answerId + revision 以及当前播放所有者。
- 范围：整份答复、若干章节、表格指定行、代码指定模块或用户选择的原文。
- 深度：standard / detailed；“简短”“只讲结论”等作为本次明确约束。
- 方式：explain / verbatim，分别表示自然解释和精确原文读取。
- 顺序：待讲单元、当前单元、已完成单元、需要补充解释的内容。
- 状态：planning / narrating / paused / suspended / completed / cancelled / failed。

先形成足够开始的结构，不等待整份长答案或所有详略版本生成完成。原始答复尚未完成时允许追加单元，但不能声称已建立最终完整范围。

### 3.3 播放记录：DeliveryLedger

每个语义单元可以对应多个 TTS 片段。记录 unitId、segmentId、计划版本、请求 ID、文本引用及 prepared / queued / playing / played / interrupted / invalidated 状态。

只有当前播放所有者的有效播放完成回报，才能将片段标记为 played。生成完成、加入队列和经过一段墙钟时间都不算。客户端回报按 session / plan / epoch 校验，其他客户端的进度不能直接合并成此用户已听完。

没有词级音频对齐时，不推断“用户听到第几个字”。恢复到最近完整句，允许重讲被打断的当前句；完整播放的章节通常不重讲。进度在上下文里称为“已播放”，不称为“用户已理解”。

## 4. 自动详略与范围规则

优先级：本次明确指令 > 当前问题及上下文 > 本次语音会话内的临时偏好 > 默认标准深度。

| 用户需求 | 系统默认行为 |
| --- | --- |
| 简单问答 | 直接完整回答，完成后结束 |
| 多部分问题 | 对应建立覆盖清单，每个子问题均有回答或明确的“暂时无法判断” |
| 教学、论证、方案设计 | 给出结论和必要推导，可连续讲解 |
| “从头讲清楚” | 直接进入详细讲解，不先停在一个很短的摘要上 |
| “太少了”“全部展开” | 当前答复切换到详细深度，自动完成相关范围 |
| “第二点详细讲” | 仅展开目标单元，保留其他部分恢复点 |
| “之后都讲详细一些” | 明确表达后才记录会话偏好；一次要求详细不永久改变所有会话 |

“全部”优先指当前逻辑答复，不自动扩大到整个会话、全部仓库或链接里的所有资料。范围明确时直接衔接并开始，例如“我按刚才的六个部分依次展开”；这不是等待确认的问题。只有歧义会显著改变对象或工作范围时才澄清一次。

取消默认 30 秒必须结束的规则。时长用于排队观察和自然分章，不作为遗漏内容的理由。用户已经要求完整讲解后，章节间自动继续，不反复询问“要继续吗”。

终点是该次计划的有限范围，不无限延伸相关知识。范围完成且没有待解释单元后自然结束，继续监听，不强制附加反问。

## 5. “全部详细讲”的执行契约

以一份包含结论、三个方案、比较表、推荐理由、实施步骤、代码和限制条件的答复为例：

1. 固定需要展开的答复版本，列出子问题、章节及工件。原文还在生成时标明范围尚未收敛。
2. 先前未讲、讲得过浅或用户明确要求重讲的部分进入计划。已有解释可简短衔接，避免无意重复。
3. 主模型以完整原文和原始依据形成解释，不能只拿先前的口头摘要继续发挥。原始资料已不可访问时明确说明，不能补造细节。
4. 按顺序讲完范围。表格转为比较，代码转为结构及运行过程，限制条件必须说出；“全部详细”不自动等于逐字符念代码和 URL。
5. “整篇重新详细讲”允许从头重复，不能因为已播记录而跳过；“补全没讲的”优先补缺，两者不同。
6. 结尾核对待讲项。达到模型或播放限制、丢失资料、合成失败时保留未完成状态，不能将队列为空当作讲完。

覆盖状态至少区分 unplanned / planned / explanation_ready / played / needs_expansion / unavailable。切换到详细深度后，标准深度的已播单元不自动满足详细要求。

覆盖清单包含主模型的语义标注。运行时可检查目标是否有对应解释、是否播放和是否有显式缺口，但不能数学证明语义无遗漏或解释正确。验收还需对照原文和问题评判，不能只凭模型自报“全部覆盖”判定通过。

用户在原答复仍生成时要求详细，不能等待已取消的旧 turn 再产出完整原文。保存已提交内容和草稿边界，将未回答的子问题带入新的详细版本；旧草稿缺失部分明确为尚未完成，不伪称已经有一份完整原文。

## 6. 混合内容的表达规则

| 内容 | 标准讲解 | 详细或全部展开 | 精确范围 |
| --- | --- | --- | --- |
| 论述和结论 | 覆盖问题、主要理由和必要条件 | 补齐论证、例子和边界 | 按选定原文读取 |
| 比较表 | 覆盖相关方案和决定判断的差异 | 按维度或逐方案解释，保留数字、单位及例外 | “每行都讲”将所有指定行纳入计划 |
| 代码 | 目的、输入输出、结果和关键约束 | 模块、控制流、关键语句和异常处理；纯代码也需要口头解释 | “逐行解释”与“逐字念”分别处理 |
| 命令和配置 | 效果、执行条件、是否实际执行 | 参数、先后依赖和验证方式 | 保留可复制原文，按明确范围精确读取 |
| 路径、链接、引用 | 对象、来源和用途 | 解释相应依据，保留重要数值 | 用户明确要求时读精确字符串 |
| 工具执行状态 | 与任务有关的真实进展和结果 | 解释发生了什么及仍欠什么 | 用户请求的可见日志可作为独立范围 |
| 失败、未验证、限制 | 必须保留，不能说成成功 | 解释影响及后续处理 | 不删除否定和限定词 |

不依据窗口失焦猜测用户是否在看屏幕。默认语音足以理解答复；屏幕承担精确展示和复制。用户明确说“我看着表格，你只讲重点”时才调整本次表达。

超大表格和长代码按可理解的组组织。用户明确要求所有行或字符时，范围应完整遍历，分组后自动继续，不能暗中退回摘要。缺失资源或实际运行限制需要说明剩余范围，不得标记完成。

## 7. 插话、继续、重讲和回应

| 表达及上下文 | 操作 | 原计划处理 |
| --- | --- | --- |
| 正在讲时说“等等，解释这个词” | 暂停并保留位置，先回答局部疑问 | 临时分支播放结束后自动接回，除非用户改变话题 |
| “先讲第二个方案” | 调整讲解顺序 | 保留其他未讲单元，之后自动接回 |
| 主动暂停后说“继续” | 恢复有效音频及原计划 | 不重新生成整篇 |
| 一次概述结束后说“继续讲” | 展开原答复的后续或更深内容 | 不在摘要字符串末尾拼接猜测 |
| “刚才那句话再说一遍” | 重讲相关完整句 | 不清空整份计划的完成状态 |
| “从第二部分重新讲” | 建立明确的重讲范围 | 保留记录，但允许用户要求的重复 |
| “嗯”“明白了”，且没有待回答的问题 | 视为简短回应，释放候选暂停 | 不取消模型、不启动新回答；“嗯，不对”不能照此过滤 |
| 正在等待用户回答时说“好” | 按当前问题理解或交给主会话 | 不一律丢弃，也不越过宿主既有确认流程 |
| “不对，我指的是另一种情况” | 停止旧输出并提交纠正 | 废止不适用的解释，明确修正，不自动接回旧结论 |
| “先不讲这个，换个问题” | 进入新主题 | 原计划挂起，不在新主题结束后擅自恢复 |
| “不用了”“停止” | 停止播放并取消当前讲解意图 | 旧回包不得再次出声，只有明确恢复才接续 |
| 空转写、回声或未提交的识别失败 | 释放候选暂停 | 保留原计划，不发空消息 |

保留现有两阶段插话：检测到语音先临时 hold，识别后再决定操作。纯播放控制本地完成，新问题和语义追问交给主会话；不要求每句话先调用一个独立分类模型。不确定的语义不能靠关键词强行执行。

保留用户原始转写。插件提供的播放位置、目标单元和恢复点作为有来源的上下文贡献，不伪装成用户说过的话。临时分支的模型输出结束但声音还没播完时，不能提前恢复原计划。

“你刚才说的那个”等指代优先绑定正在播放或最近实际播放的单元，而非模型已经写出、但尚未播到的后文。明确对象或屏幕选区优先于这种推断。向主会话提供最近完整播放的句子、当前单元、剩余范围及待回答问题，避免用户听到第二点时，模型按已经写完的第九点理解。

临时分支只有在声音播放完、没有新输入、没有待回答的问题且用户未主动暂停/停止时，才自动接回。只暂停或恢复声音不取消 LLM；确需改变回答任务时才通过宿主认可的取消/steer 流程操作，旧增量不能进入新计划。

2026-10-18 实施补充：多轮局部讨论保留挂起计划，当前主模型通过会话作用域的 `voicebox_branch(action=wait|resume|abandon)` 登记语义状态。普通语音会话无挂起计划时不提供该工具。后续用户发言之后必须重新判断，不能沿用上一轮的接回决定；未登记结束时保留挂起，用户明确说“继续讲”也可恢复原计划。`resume` 不代替播放完成回执。宿主的待回答标志同步给录入端，使无问号的提问也能保留简短回答。当前只有脚本模型的宿主契约验收，不能视为真实模型语义准确率已通过。

## 8. 模型生成及插件接入方案

### 8.1 首个实施版本的主路径

优先采用“当前会话正文适合口头解释，同时保留原生工件”的路径：

1. 只在开启语音的普通会话贡献临时表达策略及讲解状态：覆盖用户问题、自然短句、在相关位置解释工件、保留限制，详细请求自动展开。
2. 主模型照常流式生成正文及工件。自然语言解释直接进入内容单元和已有分句链路，不先生成长文再交给另一个摘要模型。
3. 复杂答复逐步补充范围、章节和工件对应关系。口头解释也是可查看内容，不能形成与屏幕无关的第二答案。
4. 普通正文和专用结构化呈现必须选定一个自动播报所有者，禁止同轮先讲一份摘要、随后又自动读全文。

此路径可复用 assistant 文本增量，减少额外模型往返。它依赖模型遵循表达策略；纯代码、纯表格或遗漏解释时要记录覆盖缺口，不能把清洗后的空串当作已讲完。

### 8.2 结构化内容与补充解释

需要模型提交章节清单及对应关系时，通过官方插件支持的结构化工具或呈现接口承载，具体注册方式在实际宿主契约验证后确定。不得从任意正文的 XML 标签、JSON 片段或文档内容推断控制指令。

待新增内部协议应满足：

- 按内容单元提交，引用答复、版本、单元及原始依据；严格字段校验、顺序号和幂等键。
- 宿主根据真实调用上下文确定 session / turn / attempt，不接受模型指定其他会话和任意播放对象。
- 工件只展示；口头解释在内容单元完成、参数校验通过后再分句。尚未完整和校验的工具参数不能直接进入 TTS。
- 一个章节可含多个段落，避免每句一次工具往返。测量其首声及章节等待，不能假定与直接正文流一样快。
- 解释缺口由同一主会话补充，补充内容用户可见并关联原答复，不默认增加独立摘要模型。

### 8.3 长输出自动接续

优先在正常模型响应内完成有限范围。输出长度限制或响应中断导致还有未讲单元时，接续携带原答复版本、已讲及待讲范围、恢复点。

自动接续只处理用户已要求的有限范围，不扩大任务、无限生成或绕过宿主既有审批。必须使用宿主认可、可追溯的内部接续机制，不能调用 beginSubmission 伪造用户说“继续”。

每次补充检查相同范围及版本的未完成项是否减少。重复同一缺口、内容改写后无进展或持续失败时停止自动补充，保存恢复点并说明剩余事项；不能靠反复生成新标题无限延长范围。

首版已在当前安装的 0.2.1-rc.1 实际 AgentLoop 中核实 `agent/turn-stopping` 与 `agent.inject` 下一步接续，以及 `agent.followup` 空闲恢复能力。内部消息使用插件来源并持久记录，不创建人工“继续”消息。真实模型是否完整解释仍需语义及人工验收；达到保护限制明确展示未完成范围，不宣称已满足完整讲解。

### 8.4 生命周期

表达策略、模型上下文和内容工具按会话及开启周期绑定，退出或卸载后释放；不覆盖用户原系统提示词，不影响其他会话或子智能体。完整提示词覆盖机制若让语音贡献失效，应识别为能力冲突，不能静默改变配置。

自然语言控制影响呈现和既有对话流程，不赋予引用资料额外权限。完整答复范围指用户可见内容，不包含内部推理或不可见系统材料。

## 9. 调度、连续性与异常

- 内容计划可以很长，音频队列保持短。默认一个正在播放和一个预取片段，其余保留为可撤销文本，避免提前生成几分钟无法及时打断的音频。
- 沿用实时 PCM。语义单元负责理解和恢复，合成片段负责声音连续性；章节边界不应导致播放器反复排空再启动。
- 预取随播放进度推进。模型或 TTS 跟不上时显示真实等待，不靠漏播后文伪装流畅。
- 旧朗读模式保留单轮 10000 字符保护；新计划按章节有限调度，增加可恢复暂存和背压。不能直接删除保护或把全部内容塞进一个队列。
- 模型 turn 结束不等于讲解结束，队列空也不等于范围覆盖。范围已收敛、解释齐备且目标单元已播放，计划才可完成。
- 暂停保留计划；停止使播放 epoch 失效。迟到的 ASR、模型增量和 TTS 回包都校验所有权，不能复活旧音频。
- 网络重试复用同一片段的幂等请求标识；用户明确要求重讲则建立新的播放计划，不能被去重逻辑误吞。
- 只对未播片段按既有质量策略重试，禁止整轮重放已出声内容。模型改写了已播内容时形成明确修正，旧稿和新稿不能混播。
- 自动恢复次数有限，遵循宿主及音质重试策略；仍失败保留恢复点并说明，不用失败声音反复重试。
- 切换其他应用或最小化不改变后台播放；监听按已有明确设置处理。切换 DSH 内部会话时暂停或停止原会话，不能串音。
- 重启及历史恢复后展示恢复入口，不自动重播或开麦。跨重启只承诺持久章节/完整句边界，不承诺恢复内存中的精确 PCM 位置。
- 保存必要的文本引用、计划和状态，沿用会话存储边界；不新增永久保存麦克风原始音频的默认行为，删除会话时清理关联计划。

## 10. 界面设计

标题栏保留入口。开启后通过已核实的输入区 dock 显示紧凑控制条，参与正常布局；目标高度 40–48px，窄窗口允许换行，为正文实际留出空间，不再用 fixed 悬窗覆盖正文和输入框。

默认可见：真实状态、麦克风静音、打断并说话、暂停/继续播放、结束语音。暂停声音和静音麦克风是独立动作。设备、音色、识别模型及说明进入详情或设置，正常对话不要求切换深度菜单。

复杂讲解可显示“正在解释：方案对比”“接回：实施步骤”。范围明确时才显示章节计数，不展示模型自报的精确语义完成百分比。

转写默认一行，可展开校正；口头讲解和原文位置可按需查看。错误就地显示，收起详情不影响播放和监听。消息下方手动朗读继续读取所选答复，不偷偷改写成摘要；精确逐字模式须明确指定。

## 11. 核心验收场景

| 编号 | 场景 | 必须观察到的结果 |
| --- | --- | --- |
| S01 | 简单事实问题 | 直接回答，不强行长报告或分章 |
| S02 | 同时问成本、利弊和步骤 | 三部分都有口头覆盖，不能只读推荐结论 |
| S03 | 正文、表格和代码混合 | 工件可复制，解释关键内容，不静默删除后宣称完整 |
| S04 | “全部详细讲一遍” | 固定范围连续展开，不逐章等待“继续” |
| S05 | “整篇重新讲”与“补充没讲的” | 前者允许完整重复，后者按缺口补齐 |
| S06 | “表格每行都讲” | 全部指定行进入计划，分组自动接续 |
| S07 | “代码逐行解释”与“逐字念” | 区分解释逻辑与读取原字符 |
| S08 | 播报中追问第二点 | 先解释目标部分，按返回条件接回 |
| S09 | 主动暂停后说“继续” | 从有效播放位置恢复，不重新生成整篇 |
| S10 | 概述结束后说“继续” | 利用完整依据展开，不在摘要后拼接猜测 |
| S11 | “嗯”“嗯，不对”“好，改一下” | 简短回应不误取消，纠正及新指令进入主会话 |
| S12 | 等待回答时说“好” | 不被回应过滤器吃掉，沿用宿主问题/确认语义 |
| S13 | 停止后迟到 ASR / TTS | 原计划取消，旧音频不得复活 |
| S14 | 只有代码或表格、没有解释 | 发现缺口；能力允许则自动补充，否则明确未完成 |
| S15 | 否定、失败和未验证 | 屏幕语音结论一致，不能说成成功 |
| S16 | 模型重试、改写、重连 | 已播不整轮重放，修正可追溯 |
| S17 | 超过旧字符上限、模型输出触顶 | 分章或合法接续；不静默截断、不伪造用户消息、不无限循环 |
| S18 | 后台播放、会话切换、重启 | 后台不断音，内部会话不串音，重启不自动重播或开麦 |
| S19 | 窄窗口、高缩放、工具面板 | 正文及输入框可用，控件无覆盖 |
| S20 | 退出、卸载、并行会话 | 表达策略和上下文及时释放，不影响其他会话 |

验证分三层：状态/所有权/范围单测；实际安装宿主的契约和 UI 测试；真实麦克风、耳机及扬声器的人工听测。模拟 PCM 调度不能代替听测，结构覆盖检查不能代替语义质量评判。

同模型、音色、文本及冷/热状态下记录 ASR、首段可播文本、首个 PCM、首声调度、段间空档和打断停声耗时，与当前实时链路比较。不能用额外语义处理换回每句中间数秒停顿；发布前依据热运行数据设回归阈值，不预先承诺未测得时延。

## 12. 实施拆分与交付门槛

1. 宿主契约及状态基础：核对实际 Desktop 的作用域、上下文、dock、结构化呈现及合法内部接续。拟新增 content.js、narration-plan.js、delivery.js 等模块和状态测试；这些不是已有文件。
2. 完整标准回答及界面迁移：接入会话表达策略、内容单元和 dock，复用当前分句/PCM。先保证多问题、混合内容和必要限制不被清洗遗漏；只迁移界面不算完成本需求。
3. 详细展开及自动接续：建立范围和深度规则，补齐工件解释及长输出接续。通过 S02–S07、S14、S17 后才能启用面向用户的“全部自动讲完”。
4. 插话及恢复：区分局部追问、顺序调整、简短回应、暂停、停止和换题；补齐恢复、重讲、迟到回包及生命周期隔离。
5. 真实验收及部署：完成 S01–S20，比较延迟并人工听测。备份后更新本地插件，保留手动朗读降级入口，核对设置及默认音色，记录实际结果。

本次交付仅为方案，未修改运行中的语音对话、播报策略和设置，也未新增 Git 提交。
